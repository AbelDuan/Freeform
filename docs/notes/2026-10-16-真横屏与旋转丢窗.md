# 2026-10-16 · 真横屏 + 旋转丢窗（v0.4.45 → v0.4.79）

## 一、小窗横竖屏「没真正实现」

### 错误做法（v0.4.44 之前）
用「关闭 → 重开 → 换一个矩形」**假装**横屏。三个致命问题：
1. 应用内容不旋转（只是窗口框变了长宽比）；
2. 每次重开都触发配置变更 ⇒ 被对账逻辑当成旋转 ⇒ **连环关窗**；
3. 与 MIUI 自己的几何逻辑并行 ⇒ 互相覆盖 ⇒ 横屏被弹回。

### ROM 自带的正确实现
反汇编 `Miui-WindowManager-Shell.jar`：

```
MiuiFreeformModeControlImpl.setRequestedOrientation(int taskId, int orientation)
  → MiuiFreeformModeController.setRequestedOrientation(taskId, orientation)   [private]
      → MiuiFreeformModeTaskInfo.setIsLandscapeFreeform(landscape)
      → MiuiFreeformModeAnimation
          .startFreeformOrientationChangeShellTransition(taskInfo)
```

这是 MIUI 横竖屏按钮真正走的路，应用内容会**真正旋转**。全程 SystemUI 侧。

### ⚠️ 最大的坑：orientation 取值
`MiuiFreeformModeController.setRequestedOrientation` 里有：

```java
boolean isLandscape = MiuiMultiWindowUtils.isOrientationLandscape(p2);
boolean current     = taskInfo.isLandscapeFreeform();
if (isLandscape == current) goto :goto_7a;    // 相同 ⇒ 直接 return，什么都不做
```

**只要取值让 `isOrientationLandscape()` 判成与当前态相同，方法就会静默 return**
（日志表现为「调用成功、无异常，但视觉无反应」）。

真机实测取值表（直接调 ROM 自己得到）：

| 取值 | isOrientationLandscape |
|---|---|
| 0, 6, 8, 11 | **true（横屏）** |
| 1, 2, 3, 4, 5, 7, 9, 10, 12, 13, 14, -1, -2, -3 | false |

⇒ 横屏应传 **6**（`SCREEN_ORIENTATION_SENSOR_LANDSCAPE`）。
（此前传 `4` = `SENSOR_LANDSCAPE` 也常被认为横屏，但**本 ROM 上 4 判为 false**，
所以一直"没反应"。）

### 调用方式
```kotlin
val ctlCls = Class.forName("com.android.wm.shell.dagger.MultiTaskingControllerImpl",
                           false, uiLoader)          // ★ 必须用注入的 ClassLoader
val ctl = ctlCls.getMethod("getInstance").invoke(null)
val modeControl = ctl.javaClass.getMethod("getMiuiFreeformModeController").invoke(ctl)
// setRequestedOrientation 是 private ⇒ 在类层次里找同名方法并 isAccessible = true
```

两个易错点：
- `Class.forName(...)` 用**默认 ClassLoader 会 ClassNotFoundException**，必须用注入的那个；
- 方法名是 `getMiuiFreeformModeController`（返回 `MiuiFreeformModeControllerStub`），
  **不是** `getMiuiFreeformModeControl`。

## 二、旋转时小窗概率性消失/重启

### 根因：模块自己造成的
真机取证（04:27）：

```
04:27:35.895  配置变更: 已重置对账计数（旋转后…）
04:27:35.898  左上角点不一致: 记忆点=43,404 实际=1394,217 ⇒ 按记忆点重开
04:27:35.898  位置/尺寸对齐: 关闭→重开到 Rect(43,404-1213,2274)
04:27:36.474  task=4448 mode=1 bounds=Rect(0,0-2364,1672)   ← 变全屏 = 用户看到的"丢失"
```

链路：**旋转 → MIUI 正常重排 → 左上角点自然变化 → 对账误判成"位置不对"
→ 关窗重开 → 中途被摆成全屏**。

而且「关闭→重开」本身又触发配置变更 ⇒ **自激循环**，连环关窗（03:57 抓到 3 连）。

### 修法
- 对账增加**旋转豁免**：配置变更后 8s 内不关窗（那是系统正常重排，不是用户挪窗）；
- 彻底移除旋转路径上的关窗重开，交回 MIUI relayout；
- 配置变更处理里，模块自发起重开期间不再排程套用（断掉自激循环）。

## 三、一并修正的真实缺陷

| 缺陷 | 根因 | 证据 |
|---|---|---|
| 多小窗上限从未生效 | `getMaxMiuiFreeFormStackCount` 在本 ROM 是 **private 且带 2 参**，原实现只挂无参重载 ⇒ 钩子数恒为 0 | 修正后 `原生=2 -> 256` |
| 重开静默失败 | 侧边栏小窗 `topActivity` 可能为空，原码 `?: return false` 直接放弃且不打日志 | 改用四层兜底的 `taskPkg()` |
| 强制横屏名单 | ROM 自带 `MiuiMultiWindowAdapter.getForceLandscapeApplication()`，命中即置横屏 | 实测已触发 |

## 四、一条走不通的路（记录以免重走）

`ActivityRecordImpl.setRequestedOrientationFreeForm`（system_server）会查 ROM 自带的
「小窗内忽略应用方向请求」名单 `getFreeformIgnoreRequestOrientationList()`：

```java
if (ignore.contains(packageName) || ignore.contains(shortComponentName))
    return;                       // 命中 ⇒ 忽略应用自己请求的方向
mMiuiFreeFormManagerService.setRequestedOrientation(orientation, task);
```

语义完全对得上「二级页面变竖屏」，但**判断名单的代码在 system_server**，
而 `android.util.MiuiMultiWindowAdapter` 只在 framework.jar 里 ——
在 **SystemUI 进程** hook 它**不会被调用到**（实测：钩子挂上了，一次都没触发）。
⇒ 该需求必须在 system_server 侧拦 `MiuiFreeFormManagerService.setRequestedOrientation`。

## 五、验证结果

| 指标 | 结果 |
|---|---|
| 旋转时关窗重开次数 | 0 |
| 变全屏（丢失）次数 | 0 |
| 旋转时模块行为 | 交给 MIUI 自行 relayout（不关窗、不重开、不闪） |
| 横屏 | ROM 原生接口，应用内容真实旋转 |

## 六、方法论教训

前几轮反复失败的根本原因是：**在没确认「窗口到底处于什么状态」的情况下就改代码**，
且一直在下游（记忆 / 对账 / 重开）打补丁。

真正解决问题靠两件事：
1. **反汇编 ROM 自己的实现**（而不是套 AOSP 常识 —— `LaunchParamsController` 那条路就是错的）；
2. **直接向系统询问它的规则**（而不是猜参数 —— 取值表就是运行时问出来的）。

用户中途两句话把方向拉了回来：
> 「你这个横屏又没真正实现，为什么旋转会消失？系统小窗旋转也不消失」
