# 通知栏下滑开小窗（移植自 HyperFreeformX 1.3.0）

> 2026-10-22 · OS4FreeFromX v0.6.4 (versionCode 122)

## 一、需求与结论

用户要求：**在 v0.6.3 基础上移植「允许通知栏下滑打开所有应用的小窗」**。

结论：系统侧的闸门是
`com.android.systemui.statusbar.notification.policy.AppMiniWindowManagerImpl#canNotificationSlide(String, PendingIntent): boolean`，
把它恒置 `true` 即可。这是 HyperFreeformX 1.3.0（`name.liuyi.hyper.freeformx`）里
`CanSlideNotification` 的做法（附件 APK 反编译确认）。

## 二、为什么 2026-10-02 那次判断错了

v0.6.3 源码里原注释写的是「长按焦点通知未进入 ModalController/小白条链路（探针零调用）」，
于是整体放弃。**真实情况（本机 MiuiSystemUI.apk 反汇编）**：

- `canNotificationSlide` 在本机有且仅有 **2 个调用方**：
  - `ExpandableNotificationRowInjector#updateFreeformTipView`
  - `ExpandableNotificationRowInjector#updateMiniWindowBar`
- 也就是说它是**通知行的小窗条开关**，不是长按链路。上次探针挂错了位置。

`updateMiniWindowBar` 的原逻辑（本机 classes2.dex）：

```smali
canSlide = appMiniWindowManager.canNotificationSlide(pkg, pendingIntent)
...
updateBackgroundForShadowAndMiniBar(...)
if (miniBarVisible) { ... getVisibleWrapper().onContentUpdated(...) }
```

即 **canSlide=true → 通知行显示「小窗条」，点它把小窗打开**。

## 三、系统原实现为什么大部分应用过不去

`canNotificationSlide` 串了一长串判断（本机 classes2.dex 反汇编）：

```
MiuiConfigs.isTinyScreen
mHasMiniWindowFeature
MiuiMultiWindowUtils.multiFreeFormSupported(context)
configuration.windowConfiguration.inMultiWindowMode
NotificationSettingsManager.mAllowNotificationSlide / mAllowNotificationSlideLocal / mDisableCloudData
PendingIntent.isActivity / isInSplitScreenWindowingMode
MiuiTopActivityObserver.mTopSplitPkgs
hasMiuiFreeformOnShellFeature（反射 getAllFreeFormStackInfosOnDisplay）
ActivityManager.MemoryInfo.lowMemory
isPinMode / isDeskModeOn
MiniWindowPolicy.slideInteractionCache（包名白名单）
微信支付特判（com.tencent.mm.framework.app.UIPageFragmentActivity）
isTopSameClass / isTopSamePackage / isSameTaskId
```

⇒ 绝大多数应用返回 false，通知行没有小窗条。恒 true 后任意应用的通知都可以。

## 四、本次改动（4 处）

| 文件 | 改动 |
| --- | --- |
| `Constants.kt` | 新增 `K_NOTIFICATION_SLIDE`、`DEF_NOTIFICATION_SLIDE=true`、`CLS_APP_MINI_WINDOW` |
| `Cfg.kt` | 新增 `@Volatile var notificationSlide`，`reload()` 读取 |
| `Hooks.kt` | `installSystemUi` 调用 `installNotificationSlide`：hook `canNotificationSlide(String, PendingIntent)` 返回 `true`（开关关闭时 `chain.proceed()`） |
| `SettingsActivity.kt` | 新增「通知栏」分组 + 开关「通知栏下滑开小窗（所有应用）」 |

默认 **开启**（与 HyperFreeformX 一致）。

## 五、构建脚本的坑（重要）

`build_local.sh` 原来只把模块类打成 `classes.dex`，**没有把 `tools/kotlin-stdlib.dex` 作为
`classes2.dex` 打进 APK**。后果：

```
E/LSPosedFramework: Error when calling onPackageLoaded of com.abel.os4freeformx
Caused by: java.lang.ClassNotFoundException: Didn't find class "kotlin.jvm.internal.Intrinsics"
on path: DexPathList[[dex file "InMemoryDexFile[cookie=[...]]"]]
```

⇒ 模块在目标进程里**一行日志都不会打**，看起来像「没注入」。
**`dist/OS4FreeFromX-v0.6.3.apk` 也是这个坏包**（单 dex、无 stdlib）。

已修：d8 之后 `cp -f "$STDLIB_DEX" "$OUT/dex/classes2.dex"`。
修复后 APK 约 744K（classes.dex 368K + classes2.dex 1.99M）。

## 六、生效与验证

1. `pm install -r`（走正规安装；LSPosed 会**自动同步** `modules.apk_path`，无需手改库）。
2. `killall com.android.systemui`（已获长期授权）。
3. LSPosed 日志（`/data/adb/lspd/log/modules_*.log`）应出现：

```
installSystemUi: immersive=true remember=true
通知栏下滑开小窗: 已挂载
通知栏下滑开小窗: canNotificationSlide → true
```

4. 注意：**单纯 `cp` 覆盖 base.apk 不生效**（ART/LSPosed 侧仍用旧 dex，实测清 oat 也无效）。
   要走 `pm install -r`。

## 七、使用方式

下拉通知栏 → 通知卡片下方会出现「小窗」条 → 点它即把该应用以小窗打开。
应用本身能不能进小窗，仍由「强制允许所有应用打开小窗」（v0.6.3 已有的 16 处解除）负责，两者互补。

## 八、开关

设置页 → 「通知栏」→ 「通知栏下滑开小窗（所有应用）」。

- 关闭后 hook 走 `chain.proceed()`，恢复系统原生判断。
- 设置页是模块 App 自己的 UI，修改后需重启模块 App 才能看到新开关项（App 进程重启需用户同意）。
